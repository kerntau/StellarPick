# 星澜优选 · 15 分钟演示脚本（真实 Juice Shop 基座）

> 启动：Windows `start.ps1` / Linux `./start.sh` → `http://127.0.0.1:8081`（hash 路由）。
> 演示前：确认 8081 只有一个 Node 进程；`npm run verify` 10/10 + 7/7 + 18/18；需要干净订单/上传时先 `POST /lab/reset?confirm=1`。
> 账号：`admin@stellarpick.example / admin123`；`alice@stellarpick.example / Alice@2026`；`bob@stellarpick.example / Bob@2026`。

## 演示话术

- 固定种子、固定账号、一键 reset：结果可重复；商品 ID 固定 1001–1020，隐藏商品 1021。
- 品牌/备案/客服/地址全部虚构，仅监听 127.0.0.1。
- V01–V10 是设计保留，不是 bug；前端不“修复”。
- V08 是真正的 Cookie CSRF：登录下发 `sp_token`（HttpOnly; Secure; SameSite=None），改邮箱接口接受该 Cookie 且不校验 CSRF token/Origin；不是“Bearer 无法跨站”的旧结论。
- V07 的 alg=none 不只影响 lab 路由：基座 `express-jwt 0.1.3 + jsonwebtoken 0.4.0` 对原生 `/api/Users` 也放行。
- V05 的列表已经按邮箱过滤，只有详情是 IDOR；这体现“正常业务过滤”和“缺失归属校验”的区别。

## 演示后清理

```powershell
# 清 lab 订单/购物车/工单/上传（不动 SQLite）
Invoke-RestMethod -Method Post 'http://127.0.0.1:8081/lab/reset?confirm=1'

# 若要恢复 alice 邮箱（V08 演示改过）
$alice = (Invoke-RestMethod 'http://127.0.0.1:8081/rest/user/login' -Method Post -ContentType 'application/json' -Body '{"email":"alice@stellarpick.example","password":"Alice@2026"}').authentication.token
Invoke-RestMethod 'http://127.0.0.1:8081/api/account/email' -Method Post -Headers @{ Authorization = "Bearer $alice" } -ContentType 'application/json' -Body '{"email":"alice@stellarpick.example"}'
```
